# 実装コストの崩壊

2025年2月、Andrej Karpathyは新しいコーディングのやり方を紹介する一つのツイートを投稿しました。「バイブに完全に身を委ね、指数的成長を受け入れ、コードが存在することすら忘れる(fully give in to the vibes, embrace exponentials, and forget that the code even exists)」やり方だ、というものでした。彼は、エージェントが出したdiffを読まずにすべて受け入れ、エラーが出たらメッセージをそのまま貼り付けると書いていました。このツイートは表示回数450万を超え、バイブコーディング(vibe coding)という名前を残しました([用語の来歴](https://www.coderabbit.ai/blog/a-semantic-history-how-the-term-vibe-coding-went-from-a-tweet-to-prod))。

重要なのは、これが皮肉でも冗談でもなかったという点です。コードを一行も読まずにすべて受け入れるやり方でも、何かが実際に完成する瞬間が来たという観察だったのです。ならば、正確に何がそれほど安くなったのかから問い直す必要があります。

## 何が実際に安くなったのか

最も確実に安くなったのは、**最初のバージョンを存在させるコスト**です。空の画面から動く何かまでの距離、プロトタイプ、ボイラープレート、慣れないライブラリの最初の接続。かつては一日かかっていたこの区間が、数分に縮みました。

ところが、より重要な変化はその隣にあります。**捨てるコストも一緒に0へ収束した**ということです。二時間かけて作ったアプローチは惜しくて抱え込んでしまいますが、20分で出てきたアプローチなら未練なく消して、別の方向を立て直せます。一つを選ぶ前に三つを実際に作ってみることが、初めて現実的な選択肢になりました。この箇所は、第3部で何に賭けるかを決める方法をあらためて扱うときに戻ってくる地点です。

この変化は組織レベルのテレメトリからも観測されます。Faros AIが1,255チーム、開発者1万人あまりのデータを分析した結果、AI導入度の高いチームではマージされたPRが98%増えました([Faros AI](https://www.faros.ai/blog/best-ai-coding-agents-2026))。コードが作られて入ってくる量そのものは、実際に二倍近く跳ね上がった計算になります。

## 何は安くならなかったのか

ここで話を止めれば、結論は一つしかありません。計画する時間があるなら作ってしまえばいい、というものです。ところが同じ時期の最も堅い実測の一つが、ちょうど逆の方向を指しています。

METRは2025年7月、熟練したオープンソース開発者16名に、自分が長く保守してきたリポジトリの実際のIssue 246件を任せ、無作為対照試験を行いました。AIツールの使用が許可された条件で、彼らは**19%遅く**作業を終えました。しかし、さらに注目すべきはその先です。実験が終わったあとも、参加者は自分が20%ほど**速くなった**と感じていました。体感と実測のあいだに39%ポイントの認識ギャップが開いたのです([METR, arXiv:2507.09089](https://arxiv.org/abs/2507.09089))。

この結果は前節を覆すものではありません。二つの結果が分かれるのは条件です。生成が速くなったのは事実であり、その利得はコードを読まずに受け入れるときにまるごと手に入ります。しかし、他人が長く責任を負ってきたコードベースで、入ってきた変更を理解し、レビューし、自分の名前でマージしなければならない瞬間、減っていたコストが別の項目として蘇ります。つまり「実装コストが0に収束する」という命題は**条件付きの真実**です。検証しない分だけ0であり、責任を持って確かめ始めた分だけ値が戻ってきます。

そして39%ポイントのギャップが語っているのは、その蘇ったコストを我々自身がうまく見えていないという事実です。プロセスを設計し直すときに体感を根拠にしてはならない理由が、ここにあります。

## 名付け親の後退

同じ結論に別の経路で辿り着いたのが、この用語を作った当人です。ツイートから1年ほど経った2026年2月、Karpathyはバイブコーディングというフレーミングを下ろし、エージェンティックエンジニアリング(agentic engineering)へと立ち位置を移しました。ツールが悪くなったからではなく、ツールが品質の臨界点を越えたことで、このフレーミングがかえって人々を誤った場所へ連れて行き始めたからです。

> 「バイブコーディングは、床を引き上げる仕事です。エージェンティックエンジニアリングは、プロフェッショナルなソフトウェアの品質基準線を守る仕事です。バイブコーディングをしたからという理由で脆弱性を招き入れることは許されません。あなたは依然として自分のソフトウェアに責任があります。」

> 「今のエージェントはインターンのような存在です。美意識、判断、趣味、監督は、依然としてあなたが握っていなければなりません。」
>
> — Andrej Karpathy ([Sequoia Ascent 2026](https://karpathy.bearblog.dev/sequoia-ascent-2026/))

1年のあいだに起きたこの用語の移動そのものが、一つの証言です。このやり方で作れるものの下限は明らかに上がりましたが、作られたものを抱えていなければならない場所は消えておらず、ただ位置が変わっただけでした。名付け親その人が「責任」と「監督」という言葉で、その新しい位置を指し示しているわけです。

では、コストは正確にどこへ移ったのでしょうか。次章で、新たに希少になった三つの資源を一つずつ見ていきます。
